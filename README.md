## 1. Что это

SQLite считает показатели по двум неделям и двум каналам. Python проверяет,
что сводка использует факты за нужную неделю и для нужного канала. Пример
сопровождает [статью на Хабре](https://habr.com/ru/companies/otus/articles/1101916/).

## 3. Требования

Bash и Python 3.12 с модулем `sqlite3`. Зависимостей из PyPI нет.

## 4. Быстрый старт

```bash
./run.sh
```

Скрипт заново собирает CSV, сверяет его с сохраненным и сравнивает весь вывод
с `expected.txt`. Расхождение дает код выхода 1.

## 5. Использование

Запрос группирует строки по неделе с понедельника и каналу. Конверсия считается
как сумма оплаченных заказов, деленная на сумму сессий, с округлением до двух
знаков. В исходных данных в сессии возможен максимум один оплаченный заказ.

Каждый случай в `data/cases.json` содержит список чисел из условного черновика
и структурированный список утверждений для проверки по фактам. Оба
представления составлены вручную для контроля. На вход проверяемой сводки
подаются идентификатор факта, показатель, единица и тип утверждения. Неделя
и канал заданы кодом. Значение для вывода берется из найденного факта.

| Случай | Сверка чисел | Сверка фактов |
| --- | --- | --- |
| Верная сводка | Принята | Принята |
| То же число из другой недели | Принята | Отклонена |
| То же число из другого канала | Принята | Отклонена |
| Неверная единица | Принята | Отклонена |
| Пропущенный KPI | Принята | Отклонена |
| Причина без доказательства | Принята | Отклонена |
| Выдуманное число | Отклонена | Отклонена |

## 6. Ограничения

Демо проверяет два KPI за одну заданную неделю и по одному каналу. Набор
случаев проверяет правила приемки. Для оценки качества модели нужны ее
фактические ответы и независимая разметка. Перед построением рабочего
отчета нужно отдельно подтвердить полноту данных и определения метрик.
При нулевом числе сессий факт конверсии отсутствует и сводка отклоняется.
